Dependency security review — GHSA-7589-6fvf-x4pw
Date: 2026-11-23

Scope and cause
Prisma CLI 7.10.1 depends on @prisma/config 7.10.1, which pins Effect
3.20.0 exactly. @prisma/client also has an optional Prisma peer; the locked
tree retains Prisma/config/Effect in a clean production-only install.
Thus npm audit --omit=dev reports three high findings for one underlying
advisory (Effect and its two affected ancestors). This is a dependency
finding, not evidence of an exploitable webhook endpoint.

The advisory affects Effect <=3.22.0. The 3.22.1 fix adds a linear matcher
for all-string TemplateLiteral spans. Other schema forms can still use
regular expressions; this change does not claim to eliminate every regex.

Remediation and compatibility
The version-scoped npm override @prisma/config@7.10.1 -> effect: 3.22.1
replaces only node_modules/effect in the lockfile. Prisma, client, adapter,
config and engines remain unchanged at their existing versions. Registry
inspection found no newer stable Prisma 7 than 7.10.1; an 8.0 release
candidate is not a suitable minimal security fix. No audit fix --force,
Prisma 6 downgrade, audit suppression or unrelated dependency upgrade ran.
Effect's fast-check and @standard-schema/spec dependency ranges are unchanged.

This overrides an upstream exact pin across Effect minor versions. It is
not automatically safe merely because the major version matches. Prisma
configuration decoding, generation, migrations and application behavior
were tested. Reassess/remove the override when Prisma ships a patched pin;
a future Prisma/config version will require a fresh audit and validation.

Regression and reproducibility
tests/effect-security.spec.ts resolves Effect from Prisma config. Valid
TemplateLiteral decoding must succeed and an adversarial 5,000-colon input
must be rejected in a bounded child process. Before the fix it fails with
ETIMEDOUT after five seconds; after the fix it passes without hanging Jest.
Node 22.20.0 / npm 10.9.3 were used. npm install --package-lock-only
--ignore-scripts --no-audit generated the lock change. A fresh npm ci
--include=dev succeeded without changing the lockfile hash. A separate
fresh npm ci --omit=dev succeeded and retained the patched Prisma chain.

CI-unblock follow-up (2026-11-23)
Only OAuth test-mock typings were ported from authentication PR #1; no auth
service/controller, cookie, redirect, CORS, CSRF, tenancy or SSE changes
were imported. Existing test cases and behavioral assertions are preserved.
The 87 diagnostics consisted of 4 consistent-type-imports, 11 explicit-any,
6 unsafe-assignment, 1 unsafe-return, 21 unsafe-call, 37 unsafe-member-access
and 7 unsafe-argument errors. Typed mock factories, explicit async mock
signatures, typed fixture boundaries and a matcher returning unknown resolve
these without changing ESLint rules or suppressing checks. Clean npm ci,
production audit, lint, typecheck and 179 unit tests pass after this port.
Exact subsequent build/integration/container and hosted CI results are
recorded in PR #2, separately from the earlier dependency-only evidence.

After the lint port, hosted PR run 45140393161 passed npm run check and
migrations, then reproduced the worker teardown error: 78 assertions passed,
but late delivery/persistence continued after Jest teardown and exited 1.
The Docker build was therefore skipped. This was the next genuine blocker,
not another lint/dependency failure.

Two deterministic lifecycle regressions fail before the worker correction
(shutdown resolves while dispatch or lease recovery is pending) and pass
after it. OutboxWorkerService now tracks active dispatch/recovery sweeps,
stops polling, and awaits active work in onModuleDestroy, before Nest invokes
the database/Redis onApplicationShutdown hooks. It starts no further claimed
messages after shutdown; unstarted leases remain available for normal stale
recovery. No sleeps, forced process exits, test suppression or data deletion
are used to hide unfinished work. The added runtime change is limited to
the worker shutdown path; authentication implementations remain untouched.
Platform termination grace periods must allow active deliveries to finish.

Merge coordination: a read-only three-way rehearsal of the OAuth test file
finds seven overlapping hunks with PR #1 (imports, mock members and callback
fixtures). Resolving those hunks to PR #1's version produces exactly its
complete test file, preserving its additional security assertions and state
cookie fixtures. When the branches are combined, retain PR #1's OAuth test
file and this branch's Effect override/regression test, and rerun checks.
Do not choose the older dependency-branch test file over the auth version.
This is a reviewed resolution plan, not a claim the branches auto-merge
without conflicts. The authentication branch itself remains unchanged.
