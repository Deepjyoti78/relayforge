Implementation
- destination_deliveries persists the first-dispatch active target snapshot,
  per-target status, reserved attempt count, next retry, active token and
  last error. Its composite primary key prevents duplicate fanout. Its
  composite FK binds the coordinator and organization. Destination IDs
  deliberately survive target deletion as tombstones; deleted targets
  become explicit dead letters instead of disappearing from completion.
- A parent is completed only when all snapshot targets succeeded. Pending
  targets keep it pending at their earliest due time. Once all targets are
  terminal, any dead target fails the event and routes its parent to DLQ.
- Each HTTP reservation is durable before egress. Target results check the
  current, unexpired parent token. A committed SUCCESS attempt is reconciled
  after a crash before the coordinator update, avoiding another known-success
  send. Replay resets unfinished targets only and retains successful targets.
- Secret resolution joins event -> originating endpoint with matching org;
  both worker and DeliveryService fallback use it. The origin's current key
  is used; no first-endpoint or unsigned fallback is introduced. A separate
  failing-before unit test verifies that, if the SQL helper is unavailable,
  a fallback endpoint from another org is rejected before signing or HTTP.
- Sweeps still handle up to 25 coordinators, claiming one just before work.
  A third optional claim-function argument excludes already visited rows.
  Existing two-argument SQL callers retain default compatibility. Live
  30-second leases renew every 10 seconds and immediately before egress.
  Lost/expired tokens cannot be renewed; renewal failure cancels active HTTP
  and stops new targets. Token fences do not claim to undo remote effects.
- Shutdown stops new claims/targets, drains dispatch, recovery and renewal,
  and persists partial progress before Nest closes PostgreSQL/Redis.
- Target transport budgets remain bounded; coordinator infrastructure/secret
  failures retry with capped backoff without consuming another target's
  transport budget. Operators must repair persistent configuration failures.
- Bulk DLQ replay now uses row locks and the same replay helper as single
  replay; concurrent calls requeue a coordinator only once. The helper also
  accepts the bulk API's historical FAILED terminal spelling. DLQ records
  identify failed target state rather than a successful sibling's latest
  attempt, and expose all remaining failed destination IDs/counters/errors.

Isolation and test configuration
Tests use restricted API/worker roles and a separate tmpfs PostgreSQL/Redis
project on loopback ports 55435/56382, database relayforge_reliability_test.
Only fixture data in that disposable database is changed. The test-only
ALLOW_PRIVATE_DESTINATIONS flag permits loopback HTTP recipients; production
still rejects it. No production env file or OAuth credentials are used.
New target-state reads require org membership under forced RLS; API writes
are denied. Mutation helpers are worker-only, fixed-search-path functions
with PUBLIC execution revoked. Origin-secret API lookup requires matching
tenant context. Existing end-user replay authorization is retained.

Guarantees and remaining limits
See delivery-architecture.md for the public contract. Delivery is bounded,
at-least-once attempt semantics, not an unconditional receipt or exactly-once
side-effect guarantee. A receipt followed by process death before durable
acknowledgement can be resent with the same logical ID; receivers must use
atomic, durable deduplication. HTTP cannot participate in the database commit.
Loss of database connectivity, event-loop stalls, partitions and forced
termination can still produce ambiguous receipt. A crash before egress can
consume a reserved attempt. Secret rotation uses the origin's current key.
Target membership snapshots at first dispatch; later additions are excluded,
while retries use current target config. Deletion/retention policies still
apply; deleting an endpoint cascades its event/outbox data as before.
Existing workflow step-side-effect semantics, Redis limiter fail-open behavior,
the five-minute Retry-After cap and existing replay restrictions are retained.
Historical invalid coordinator rows require operator audit; new normal fanout
failures use DEAD_LETTER. Persistent infrastructure/key
problems can remain pending until repaired; monitor coordinator retries/DLQ.
The pre-existing four updated_at default differences and organizations
created_by index/schema drift must remain visible; this is not a drift repair.
